# ServiceDesk ПМ

Информационная система автоматизации ИТ-поддержки ООО «Поисковая машина».
Состоит из веб-портала на Django и бота для ВКонтакте и мессенджера MAX.

## Запуск в PyCharm

1. **File → Open** и выберите папку проекта.
2. PyCharm предложит создать виртуальное окружение из `requirements.txt`: нажмите **OK**.
   Если не предложил: **Settings → Project → Python Interpreter → Add Interpreter → Virtualenv**,
   затем откройте `requirements.txt` и нажмите в жёлтой плашке **Install requirements**.
3. Вверху справа, в выпадающем списке конфигураций, уже есть готовые варианты запуска:

| Конфигурация | Что делает |
|---|---|
| **1. Подготовка базы (первый запуск)** | создаёт таблицы и загружает демо-данные (~250 заявок). Запустить один раз |
| **2. Сайт** | веб-портал на http://127.0.0.1:8000 |
| **3. Проверка SLA** | раз в минуту: напоминания, эскалация, автозакрытие |
| **▶ Сайт + SLA** | запускает оба сразу |
| **4. Бот ВКонтакте** / **5. Бот MAX** | боты (сначала впишите токены в `.env`) |
| Тесты | 13 автотестов |
| Пересоздать демо-данные | очистить базу и заново заполнить примерами |
| Создать администратора | свой логин для `/admin/` |
| Обновить базу знаний | загрузить статьи из `helpdesk/kb_data.py` (после правок в этом файле) |

Выберите конфигурацию и нажмите ▶ (или **Shift+F10**). Для отладки с точками останова нажмите 🐞 (**Shift+F9**).

Настройки (токены ботов, база данных) хранятся в файле `.env`. Скопируйте `.env.example` в `.env` и заполните.
Для локального запуска `.env` можно не создавать, тогда используются значения по умолчанию и база SQLite.

Без PyCharm, из терминала:

```bash
pip install -r requirements.txt
python manage.py init_project
python manage.py runserver
```

## Установка на сервер

Коротко: Linux-сервер, Docker и одна команда `docker compose up -d --build`. Поднимаются сайт (gunicorn),
PostgreSQL, проверка SLA, боты и Caddy с автоматическим HTTPS-сертификатом.
Пошаговая инструкция: **[docs/DEPLOY.md](docs/DEPLOY.md)**.

## Подключение ботов

Бот работает как отдельная программа рядом с сайтом и использует ту же базу данных.\
Локально бот запускается конфигурацией PyCharm «4. Бот ВКонтакте» или «5. Бот MAX». На сервере он запускается вместе со всем остальным, см. [docs/DEPLOY.md](docs/DEPLOY.md).

### ВКонтакте

1. Создайте сообщество (подойдёт закрытое), например «ИТ-поддержка ПМ».
2. **Управление → Сообщения**: включите сообщения сообщества.
   **Сообщения → Настройки для бота**: включите возможности ботов и кнопку «Начать».
3. **Управление → Работа с API → Ключи доступа**: создайте ключ с правом «Сообщения сообщества».
4. **Работа с API → Long Poll API**: включите его, выберите версию **5.199**, а на вкладке «Типы событий» отметьте «Входящее сообщение».
5. В файл `.env` впишите `VK_TOKEN=<ключ>` и `VK_GROUP_ID=<ID сообщества, только цифры>`.
6. Запустите конфигурацию «4. Бот ВКонтакте».

### MAX

1. Создайте бота в MAX: через @MasterBot или на платформе для бизнеса MAX (dev.max.ru). Получите токен.
2. Впишите в `.env`: `MAX_TOKEN=<токен>`.
3. Запустите конфигурацию «5. Бот MAX».

> API MAX появился недавно и ещё меняется. Если бот не отвечает, сверьте адрес API (`MAX_API_URL`)
> и формат запросов с документацией на dev.max.ru. Все обращения к API собраны в файле `helpdesk/bots/max.py`
> (функции `call`, `send`, `_dispatch`), так что поправить нужно только их.

### Как сотрудник начинает пользоваться ботом

1. Входит на портал и открывает **Профиль и боты**, там показан 6-значный код.
2. Пишет боту этот код. Аккаунт привязывается, и бот узнаёт сотрудника.
3. Дальше всё делается кнопками: «Новая заявка», «Мои заявки», «База знаний».
   В этот же чат приходят уведомления о смене статуса, ответы специалиста (кнопка «Ответить») и запрос на оценку.

## База знаний

43 инструкции по 7 категориям: пароли и доступы, VPN и сеть, принтеры и оборудование, программы, почта и телефония, 1С, информационная безопасность.
Статьи хранятся в файле **`helpdesk/kb_data.py`**. У каждой есть ключевые слова: по ним работают подсказки при создании заявки и поиск в боте.

- Добавить или изменить статью можно в `kb_data.py` (затем запустите «Обновить базу знаний») или прямо в админке `/admin/` → «База знаний».
- Внутренние адреса и телефоны в статьях (`passwd.poisk.local`, `vpn.poisk.ru`, внутренний 1234 и т. п.) условные. Перед реальным внедрением замените их. Список всех условных адресов приведён в начале `kb_data.py`.
- Сайт при запуске сам добавляет в базу недостающие статьи из файла. Уже существующие статьи он не перезаписывает.

## Уведомления на почту

Все уведомления, которые приходят в мессенджеры, дублируются на e-mail: создание заявки, ответ специалиста,
смена статуса, напоминания и эскалации по SLA. В письме есть ссылка на заявку.
Сотрудник указывает свою почту и может отключить письма в разделе **«Профиль и боты»**.

**Без настройки** письма не отправляются, а печатаются во вкладке «2. Сайт» в PyCharm. Так удобно проверять.

**Чтобы письма уходили по-настоящему,** заполните в `.env` данные почтового ящика, с которого будет идти отправка:

```
EMAIL_HOST=smtp.yandex.ru
EMAIL_PORT=465
EMAIL_HOST_USER=helpdesk-pm@yandex.ru
EMAIL_HOST_PASSWORD=пароль_приложения
```

Для Яндекса и Mail.ru обычный пароль не подойдёт, нужен **пароль приложения**:
- Яндекс: id.yandex.ru → «Безопасность» → «Пароли приложений» → «Почта»;
- Mail.ru: «Настройки» → «Безопасность» → «Пароли для внешних приложений».

После изменения `.env` перезапустите сайт.

## Структура проекта

```
config/                     настройки Django
helpdesk/
  models.py                 модель данных: заявки, категории, SLA, база знаний…
  services/                 ★ бизнес-логика и алгоритмы автоматизации
    classifier.py             автоклассификация и приоритет
    assignment.py             автоназначение исполнителя (балансировка нагрузки)
    tickets.py                жизненный цикл заявки, контроль SLA, эскалация, автозакрытие
    kb.py                     поиск статей базы знаний
    notify.py                 уведомления в мессенджеры
    text.py                   обработка русского текста
  bots/
    base.py                   общие структуры: кнопка и ответ
    core.py                   ★ сценарий диалога, общий для всех мессенджеров
    vk.py                     адаптер ВКонтакте
    max.py                    адаптер MAX
  management/commands/      init_project, seed_demo, check_sla, run_vk_bot, run_max_bot
  templates/                страницы сайта (Bootstrap 5)
  static/helpdesk/vendor/   Bootstrap и Chart.js лежат локально, интернет не нужен
  tests.py                  автотесты
.idea/runConfigurations/    готовые конфигурации запуска PyCharm
Dockerfile, docker-compose.yml, deploy/   установка на сервер
```

**Архитектурная идея для диплома.** Сайт и боты не содержат бизнес-логики. Они вызывают одни и те же функции
из `services/`, поэтому правила работают одинаково для любого канала. Логика бота (`core.py`) не зависит
от мессенджера: чтобы добавить, например, Telegram, достаточно написать ещё один адаптер на 60–80 строк.

## Алгоритмы автоматизации (кратко для главы 2)

1. **Классификация.** Для каждой категории считается вес: совпадение ключевого слова в теме даёт 2 балла, в описании 1 балл. Побеждает категория с наибольшим весом, а уверенность равна её доле в сумме весов. Ключевые слова редактируются в админке.
2. **Приоритет.** Берётся из категории. Слова-маркеры массового сбоя («у всех», «сервер упал», «вирус») повышают его до «Критического», а заявки руководства компании получают приоритет на один уровень выше.
3. **SLA.** Срок решения равен времени создания плюс норматив для приоритета (Низкий 3 дня, Средний 8 ч, Высокий 4 ч, Критический 1 ч).
4. **Назначение.** Заявка уходит специалисту из группы, отвечающей за категорию, у которого меньше всего открытых заявок.
5. **Контроль SLA** (`check_sla`, раз в минуту). Когда осталось меньше 25% времени, исполнителю приходит напоминание. После просрочки заявка эскалируется руководителю ИТ. Решённая заявка без подтверждения автора закрывается через 3 дня.
6. **Самообслуживание.** Пока сотрудник печатает, система подсказывает статьи базы знаний. Нажатие «Помогло» засчитывается как обращение, решённое без специалиста.
