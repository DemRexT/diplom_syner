# ServiceDesk ПМ

Информационная система автоматизации ИТ-поддержки ООО «Поисковая машина».
Состоит из веб-портала на Django и бота для ВКонтакте и мессенджера MAX.

## Быстрый старт (Windows)

1. Установите **Python 3.11 или новее** с сайта python.org. В установщике отметьте галочку **Add python.exe to PATH**.
2. Распакуйте архив в папку, путь к которой лучше без пробелов, например `C:\servicedesk`.
3. Дважды щёлкните **`setup.bat`**. Скрипт установит библиотеки, создаст базу данных и заполнит её демо-данными (около 250 заявок за 60 дней).
4. Дважды щёлкните **`run_site.bat`**: сайт откроется по адресу http://127.0.0.1:8000.
5. Чтобы работали напоминания, эскалация и автозакрытие заявок, запустите **`run_sla.bat`** и держите это окно открытым.

## Подключение ботов

Бот работает как отдельная программа рядом с сайтом и использует ту же базу данных.
Сайт при этом должен быть запущен, иначе ссылки из сообщений бота открываться не будут.

### ВКонтакте

1. Создайте сообщество (подойдёт закрытое), например «ИТ-поддержка ПМ».
2. **Управление → Сообщения**: включите сообщения сообщества.
   **Сообщения → Настройки для бота**: включите возможности ботов и кнопку «Начать».
3. **Управление → Работа с API → Ключи доступа**: создайте ключ с правом «Сообщения сообщества».
4. **Работа с API → Long Poll API**: включите его, выберите версию **5.199**, а на вкладке «Типы событий» отметьте «Входящее сообщение».
5. В файл `.env` впишите `VK_TOKEN=<ключ>` и `VK_GROUP_ID=<ID сообщества, только цифры>`.
6. Запустите `run_vk_bot.bat`.

### MAX

1. Создайте бота в MAX: через @MasterBot или на платформе для бизнеса MAX (dev.max.ru). Получите токен.
2. Впишите в `.env`: `MAX_TOKEN=<токен>`.
3. Запустите `run_max_bot.bat`.

> API MAX появился недавно и ещё меняется. Если бот не отвечает, сверьте адрес API (`MAX_API_URL`)
> и формат запросов с документацией на dev.max.ru. Все обращения к API собраны в файле `helpdesk/bots/max.py`
> (функции `call`, `send`, `_dispatch`), так что поправить нужно только их.

### Как сотрудник начинает пользоваться ботом

1. Входит на портал и открывает **Профиль и боты**, там показан 6-значный код.
2. Пишет боту этот код. Аккаунт привязывается, и бот узнаёт сотрудника.
3. Дальше всё делается кнопками: «Новая заявка», «Мои заявки», «База знаний».
   В этот же чат приходят уведомления о смене статуса, ответы специалиста (кнопка «Ответить») и запрос на оценку.

## Структура проекта

```
config/                     настройки Django
helpdesk/
  models.py                 модель данных: заявки, категории, SLA, база знаний…
  services/                 ★ бизнес-логика и алгоритмы автоматизации
    classifier.py             автоклассификация и приоритет
    assignment.py             автоназначение исполнителя (балансировка нагрузки)
    tickets.py                жизненный цикл заявки, контроль SLA, эскалация, автозакрытие
    kb.py                     поиск статей базы знаний
    notify.py                 уведомления в мессенджеры
    text.py                   обработка русского текста
  bots/
    base.py                   общие структуры: кнопка и ответ
    core.py                   ★ сценарий диалога, общий для всех мессенджеров
    vk.py                     адаптер ВКонтакте
    max.py                    адаптер MAX
  management/commands/      seed_demo, check_sla, run_vk_bot, run_max_bot
  templates/                страницы сайта (Bootstrap 5)
  static/helpdesk/vendor/   Bootstrap и Chart.js лежат локально, интернет не нужен
  tests.py                  автотесты
```

**Архитектурная идея для диплома.** Сайт и боты не содержат бизнес-логики. Они вызывают одни и те же функции
из `services/`, поэтому правила работают одинаково для любого канала. Логика бота (`core.py`) не зависит
от мессенджера: чтобы добавить, например, Telegram, достаточно написать ещё один адаптер на 60–80 строк.

## Алгоритмы автоматизации (кратко для главы 2)

1. **Классификация.** Для каждой категории считается вес: совпадение ключевого слова в теме даёт 2 балла, в описании 1 балл. Побеждает категория с наибольшим весом, а уверенность равна её доле в сумме весов. Ключевые слова редактируются в админке.
2. **Приоритет.** Берётся из категории. Слова-маркеры массового сбоя («у всех», «сервер упал», «вирус») повышают его до «Критического», а заявки руководства компании получают приоритет на один уровень выше.
3. **SLA.** Срок решения равен времени создания плюс норматив для приоритета (Низкий 3 дня, Средний 8 ч, Высокий 4 ч, Критический 1 ч).
4. **Назначение.** Заявка уходит специалисту из группы, отвечающей за категорию, у которого меньше всего открытых заявок.
5. **Контроль SLA** (`check_sla`, раз в минуту). Когда осталось меньше 25% времени, исполнителю приходит напоминание. После просрочки заявка эскалируется руководителю ИТ. Решённая заявка без подтверждения автора закрывается через 3 дня.
6. **Самообслуживание.** Пока сотрудник печатает, система подсказывает статьи базы знаний. Нажатие «Помогло» засчитывается как обращение, решённое без специалиста.
